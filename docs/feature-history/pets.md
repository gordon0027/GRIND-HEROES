# Pet System V1

Pet ownership is represented by three nontradable, stackable iDos Items. The native Store offers grant exactly one Item and have a per-player `TotalCap: 1`; the same Store transaction consumes GOLD, GEMS, or `CryptoCurrencies.Main`. The client never grants pet Items. `grind_pets_v1` is a ReadOnly UserCustomData JSON key containing the equipped ID and an optional pending ID. CloudCode checks actual Item counts before accepting any selection. A removed Item loses its bonus even if the protected selected ID remains.

There is one account pet, shared by the current formation. A selection during an active server run stays pending; `startStageRun` applies it at the next boundary and returns the chosen ID to the client. Combat and the server Team Power/Top 100 projection add the same flat Attack and HP values **after** archetype scaling and gear, once per active hero. `powerFormula.js`, caps, and gear slots are unchanged. The three names, test prices, bonuses and asset keys in `server/pets.js` are provisional. Store config owns the actual charge; `resolvePetOffer` refuses an offer that does not match the server catalog. `PetsSection` maps asset keys to `null` placeholders, ready for final PNG paths.

DEV title `98JRCAKG-DEV` has all three Item definitions, one-time Store offers, protected key, and CloudCode revision 32 with pet and Team Power handlers. GOLD and GEMS purchases, repeat rejection, ownership checks, queued selection, unequip, and leaderboard changes passed live DEV guest probes. DEV has no `Currency.CryptoCurrencies.Main`; a direct GH offer purchase returns `CC Main: not found in definitions`. GH spend and a relogin/device persistence check are still unverified.
